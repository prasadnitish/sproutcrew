An illustrative workflow. You review the evidence and final recommendation.

  1. 01

    Bring the context.

    Add the brief, notes, reports, or public page URLs. Save project instructions for the audience, voice and decisions the crew should follow.

  2. 02

    Review the plan and permissions.

    Choose the steps and models. Inspect what each role may do, then approve execution. Editing the plan, policy or material source context requires a new approval.

    Asking AI to draft or reshape the plan uses provider allowance before execution approval.

  3. 03

    Decide what changes.

    Read the draft and its review findings. Accept a finding, reject it with a reason, or keep it in the decision inbox for your judgment. Choose different providers for the author and reviewer; a pass on one provider remains a second pass.

  4. 04

    Export the document and the record.

    Keep the final work alongside a run report: the approved scope, policy decisions, review history, artifact hashes and reported usage. Run reports export as Markdown and PDF when the helper is available; a missing PDF is reported.

Supervision is the product.

Review an execution plan before the crew starts its tasks. Keep findings and outstanding decisions in view, then decide what to revise or export.

Enforcement, not suggestion.

The Rust core binds approval to the plan, action policy and material context. It checks app-owned actions against role permissions and blocks new dispatch when that approval changes.

These checks do not make model reasoning immune to prompt injection or create an operating-system sandbox.

Every engine, one board — and a bill you can read.

Bring supported provider API keys and assign the models to the work. Requests reserve their configured bounds before dispatch. Usage that cannot be verified stays unknown.

Supported API routes are available in the Mac build. Subscription CLI connections stay disabled.

API dollars, tokens and any available plan-window readings stay separate. Each entry carries its status: reported, estimated, reconciled or unknown. The current build connects through APIs and does not consume subscription-plan allowances.

Paid OpenRouter models stop at $5 for each project unless you raise that limit, and a request whose price is unknown is refused. Other providers are held by a token limit, which is not a dollar cap. What this build covers

Can it control my browser or other apps?

This build does not take screenshots, click through websites, type into other apps, or control your desktop. You can add public URLs as sources. That is different from browser or computer control.

Can I use a ChatGPT or Claude subscription?

This build accepts provider API keys. Your subscription login does not connect it. Any API credits offered by a provider have their own eligibility, billing and expiry rules.

Can the crew search the web for me?

Yes, if you turn on web research when you create a project. The research step sees only your brief, never your files, and lists every page it used. It needs a paid model, and OpenRouter charges a small fee for each search. You can also add files and public page URLs as sources. Check the resulting citations yourself.

What about code work?

Projects that write code are off until you turn on Allow projects that write running code in Settings. Then App development and clickable prototypes are offered. Code is shown to you for review, a prototype opens only in the app’s own preview, and generated commands and dependency installs do not run on your Mac.

Will it tell me when my input is needed?

The Decision inbox shows pending approvals, review findings, action requests and stopped steps across projects. Turn on optional Mac alerts in Settings to get a generic notification for new items while SproutCrew is in the background. Keep the app open or minimized; macOS permissions, Focus and screen-sharing settings control delivery. Notifications never approve work.

What happens if I press Stop?

Stop prevents further work from starting. A request already sent to a provider can still finish or be billed. The app keeps reported usage when it is available.
